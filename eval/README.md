# Mini eval-сет для retrieval

`retrieval_mini.jsonl` — 12 пар «вопрос → ожидаемый пункт», размеченных вручную
по реальному содержимому проиндексированного корпуса.

Одна строка — один вопрос:

```json
{"id": "q01", "language": "ru", "query": "...", "expected": [{"source_file": "...", "clause_id": "5.3"}]}
```

`expected` — список: попадание засчитывается, если в top-k оказался **любой** из
перечисленных пунктов. Это нужно там, где ответ законно лежит в соседних пунктах
(например `Section 10.1` и `Section 10.1.1`), и оставляет место для будущих
вопросов с несколькими верными источниками.

Двуязычные договоры дают один и тот же `clause_id` на казахской и русской версии
пункта — засчитывается любая из них.

## Запуск

Требуется применённая миграция `002` и заполненная таблица `contract_chunks`:

```bash
uv run python eval/run_retrieval_eval.py
```

Скрипт ходит в живой Supabase, поэтому он намеренно вынесен из `tests/` и не
собирается pytest'ом.
